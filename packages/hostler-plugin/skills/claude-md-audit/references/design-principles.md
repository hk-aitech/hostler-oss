# CLAUDE.md optimization design principles P1~P7

The seven design principles derived in §4 of the research report
(`docs/08-references/research/claude-md-optimization-research.md`). The
`claude-md-audit` skill uses them when judging per-section migrations.

## P1 — Universal Context Only

CLAUDE.md keeps **only context needed in every session**. Information that's
only needed at a particular moment / task / project phase is split off so it
loads only when that moment arrives.

**Examples**:
- ✅ keep: code-writing rules, Korean commit-message rule
- ❌ migrate: "Roadmap" (completed history + P2/P3 TODO) — roadmap.md
- ❌ migrate: "detailed list of adopted projects" — collapse to a short bullet

**Rationale**: CLAUDE.md is injected into the entire system prompt at every
session start. Unnecessary context wastes the token budget and degrades
adherence.

## P2 — Action > Knowledge

"Do X" (action) takes priority over "X exists" (reference). Imperative
instructions stay; explanations / background / history move to reference docs.

**Examples**:
- ✅ keep: "Forbid magic numbers — extract to `const` or environment variables"
- ❌ migrate: "Detailed table of 9 environment variables" — pointer to configuration.md

**Rationale**: LLMs respond more strongly to action instructions. Reference
information loads more efficiently on demand.

## P3 — Reference > Duplicate

Don't repeat detail; keep only reference pointers. The SSOT lives in a
separate doc, and CLAUDE.md only says "look there".

**Examples**:
- ✅ keep: "9 environment variables (`HOSTLER_OSS_` prefix) — see configuration.md §4"
- ❌ migrate: 9-row environment-variable table (duplicates configuration.md)

**Rationale**: duplicated info risks drift. SSOT preservation guarantees
consistency.

## P4 — Path-scoped Rules

Rules specific to file types / directories move to `.claude/rules/*.md` +
`paths` frontmatter. Claude Code auto-loads them only when those files are
edited.

**Examples**:
- ✅ keep: pointer section "## Development standards (Skill / MCP Tool / Command)"
- ❌ migrate:
  - 138 lines of skill development standards → `.claude/rules/skill-development.md` (paths: `skills/**/*`)
  - 71 lines of MCP Tool development standards → `.claude/rules/mcp-tool-development.md` (paths: `cli/**/*.go`)
  - 46 lines of Command development standards → `.claude/rules/command-development.md` (paths: `commands/**/*.md`)

**Rationale**: Anthropic's official docs formally support `.claude/rules/` +
`paths`. In sessions where those files aren't edited, the rules don't get
injected, saving tokens.

**Verification**: see `docs/06-reports/measurements/claude-md-paths-scoping.md`.

## P5 — Auto-generated Index

Manually maintained lists (skill-trigger tables, API indexes, etc.) get
auto-generated by scripts. Deterministic output lands under
`docs/03-design/`.

**Examples**:
- ✅ keep: pointer "Skill trigger summary is generated from `skills/*/SKILL.md`"
- ❌ migrate: 33 lines of manual trigger table → run `scripts/generate-skill-triggers.py`

**Rationale**: drift is inevitable when maintained manually. We caught one
missing skill in the manual table (manual table 30 vs actual 31).

## P6 — Version-aware Pointers

Version / status / history information goes into separate documents
(`roadmap.md`, `CHANGELOG.md`). CLAUDE.md keeps only "currently active rules".

**Examples**:
- ✅ keep: "details in `docs/00-project/roadmap.md`"
- ❌ migrate: "P2 Skills advanced features completion checkboxes (17 items)" → roadmap.md

**Rationale**: history / completion info doesn't need to be reloaded every
session. The AI can fetch it on demand via the Read tool.

## P7 — Universal Rules First

Section order: **core rules at the top, metadata at the bottom**. The AI
should encounter the most important principles within the first 200 tokens.

**Example structure**:

1. Title + intro
2. Core rules: code writing / Command-first / MCP-first / capture lessons
3. Unified development-standards pointer
4. Metadata: env variables / skill triggers / status

**Rationale**: CLAUDE.md is injected as a user message right after the system
prompt, and LLM attention concentrates on early tokens. Important
instructions go up top.

## Priority when principles conflict

- P1 > P7: decide "keep at all" first (P1), then ordering (P7)
- P4 > P3: prefer `.claude/rules/` (duplication permitted) when path-scoping
  is possible; fall back to a single SSOT under docs/ (P3) when it isn't
- P2 > P5: action-first ("auto-generate the skill trigger" vs "the skill
  trigger list exists")
